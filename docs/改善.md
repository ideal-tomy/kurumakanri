# Shaken Notify UI/UX 改善 実装計画書

## 背景・目的

板金屋（車関係）向け顧客管理システム「Shaken Notify」のUI/UX改善。

**前提**:
- バックエンド（Supabase + LINE Messaging API）はほぼ完成
- 現状のフロントは Next.js 14 (App Router) + Tailwind CSS で実装済み
- スマホで使われる前提
- **想定ユーザー: ITリテラシーが低い担当者・経営者（50代〜60代の整備士・店主が中心）**

**改善ゴール**:
- スマホ片手で全業務が完結する操作性
- 1タップで主要アクション（電話/LINE送信/対応済み）が実行できる
- 入力作業の心理的ハードルを下げ、データ登録を進めやすくする
- 視覚的な情報階層を整理し、「今すぐ何をすべきか」が一目でわかる

---

## 現状の課題（スクショ分析）

### ダッシュボード画面
- 「ダッシュボード」のセリフ体タイトルが画面の1/4を占有し情報密度が低い
- 「期限が近い顧客」のテーブルでナンバーが折り返し表示されて読みにくい（横浜/300/こ/78-90 が縦4行）
- リストから直接アクション（電話・LINE送信）ができない
- 残日数が全部赤色で表示され、緊急度（15日 vs 40日）の区別がつかない
- 統計カード（19台/5件/6件/19件）が同じサイズで並び、何が重要か伝わらない

### 顧客追加フォーム
- 入力項目が縦に長く並び、最初の壁が高い
- LINE USERID という技術項目が上の方に出ていて混乱を招く
- 必須項目と任意項目の区別が弱い
- どこまで入力すれば登録完了なのか不明

### タスク管理画面
- フィルターボタンが6個（今週の送信候補/すべて/未完了/手動タスク/自動候補/完了）あり、選択肢が多すぎる
- 「手動タスク/自動候補」はシステム都合の区別でユーザーには不要な情報

## 実装フェーズ

### 🔴 Phase 1: 操作性の根本改善（最優先・1〜2スプリント）

最初に着手するのはここ。これだけで体感的な使いやすさが激変する。

#### 1-1. 一覧カードからの直接アクション

**対象ファイル**: `app/dashboard/page.tsx`、新規 `components/CustomerActionCard.tsx`

**実装内容**:
- 「期限が近い顧客」リストの各行を独立カード化
- 各カードに3つのアクションボタンを配置:
  - **LINE送信ボタン**: 緑色。タップで定型文をMessaging API経由で送信
  - **電話ボタン**: 青色。`tel:` リンクで即発信
  - **完了ボタン**: グレー。`notifications` テーブルのステータスを `acknowledged` に更新
- LINE送信時の定型文はテンプレート化して `lib/message-templates.ts` に集約
  - 例: `車検6ヶ月前`、`車検3ヶ月前`、`車検1ヶ月前`、`オイル交換目安` で別テンプレート

**完了条件**:
- 一覧画面から詳細に飛ばずに、3つの主要操作が1タップで完了する
- 送信/発信/完了の各操作後、トーストで結果フィードバックが出る

#### 1-2. 残日数の色分け（緊急度の可視化）

**対象ファイル**: `components/CustomerActionCard.tsx`、`lib/urgency.ts`（新規）

**実装内容**:
- 残日数に応じて3段階の緊急度を計算するユーティリティを作成
  ```ts
  // lib/urgency.ts
  export type UrgencyLevel = 'critical' | 'warning' | 'normal';
  export function getUrgencyLevel(daysRemaining: number): UrgencyLevel {
    if (daysRemaining <= 30) return 'critical';
    if (daysRemaining <= 90) return 'warning';
    return 'normal';
  }
  ```
- カードの左端に4pxの色付き縦線（border-left）で表現
  - critical: 赤 (#E24B4A)
  - warning: オレンジ (#EF9F27)
  - normal: グレー (#888780)
- 残日数の数字も同じカラーパレットで色分け

**完了条件**:
- 残日数15日と40日のカードが、視覚的に明確に区別される

#### 1-3. タップ領域の拡大

**対象ファイル**: 全インタラクティブ要素

**実装内容**:
- すべてのボタン・リンクの最小タップ領域を 44×44px に揃える
- ボタン同士の最小間隔を 8px 以上確保
- Tailwindクラス共通化: `min-h-[44px] min-w-[44px]` をボタン基本クラスとして定義

**完了条件**:
- どのボタンも、太い指でも誤タップしない大きさ・間隔になっている

### 🟡 Phase 2: 情報設計の見直し（2〜3スプリント目）

#### 2-1. 入力フォームの3ステップ分割

**対象ファイル**: `app/customers/new/page.tsx` を全面リファクタ、新規 `components/forms/Step1Required.tsx` 等

**実装内容**:
- 1ページの長いフォームを3ステップウィザードに分割
  - **ステップ1（必須・最低限）**: 氏名・電話・ナンバー・車検満了日
  - **ステップ2（推奨）**: メーカー・車種・走行距離・最終オイル交換日
  - **ステップ3（任意）**: 住所・メール・メモ
- 上部にステップインジケータ表示（1/3 → 2/3 → 3/3）
- 各ステップに「ここまでで保存して終了」ボタンを配置
- ステップ1完了時点で `customers` テーブル + `vehicles` テーブルへ登録完了する設計
- ステップ2以降は `vehicles` テーブルの追加カラム更新
- LINE USERID 等の技術項目はUIから完全除外（フェーズ3の友だち追加時に自動取得）

**完了条件**:
- ステップ1の4項目だけで顧客登録が完了でき、通知対象に含まれる
- 途中で「保存して終了」を押しても、入力済みデータは保存される

#### 2-2. ナンバーの構造化入力

**対象ファイル**: 新規 `components/forms/PlateNumberInput.tsx`

**実装内容**:
- 1つのテキストフィールドではなく、4分割の入力欄に
  - 地名（プルダウン: 横浜・品川・大宮 など主要なものを選択肢化）
  - 分類番号（数字3桁の input、type="number" は使わず inputMode="numeric"）
  - ひらがな（プルダウン: あ・い・う...・を）
  - 一連指定番号（数字、ハイフン自動挿入）
- DBへの保存形式は従来通りの単一文字列（例: "横浜300あ12-34"）。表示時のみ分割
- DB側マイグレーションは不要（保存形式は変えない）

**完了条件**:
- 入力フォーマットが揺れない（半角/全角混在しない）
- 既存データの表示も問題なく動作する

#### 2-3. 日付入力の改善（クイックボタン）

**対象ファイル**: 新規 `components/forms/DatePickerWithQuickButtons.tsx`

**実装内容**:
- 通常の `<input type="date">` の上に、クイックボタンを併設
  - 「1年後」「2年後」「3年後」のチップボタン
- クイックボタンを押すと該当日が自動入力される（タップで toggle ではなく即適用）
- 車検満了日は2年後 or 3年後がほとんどなので、これだけで入力が劇的に楽になる

**完了条件**:
- 車検満了日入力が、ほぼタップ1回で完了する

### 🔵 Phase 4: 品質を上げる仕掛け（4スプリント目以降）

#### 4-1. 確認ダイアログの簡素化

**対象ファイル**: 新規 `components/BottomSheet.tsx`

**実装内容**:
- ブラウザの `confirm()` を使用している箇所を、下からスライドアップするボトムシートに置換
- 「送信する」「キャンセル」の2ボタンを大きめ（min-height: 56px）に配置
- 主要ボタンは右、副次ボタンは左の配置
- ライブラリは `@radix-ui/react-dialog` または自前実装でOK

**完了条件**:
- すべての確認操作がデザイン統一されたUIで行われる

#### 4-2. エラーメッセージの日本語化

**対象ファイル**: 新規 `lib/error-messages.ts`

**実装内容**:
- Supabase / LINE API のエラーコードを日本語に変換するマップ層を作る
  ```ts
  // lib/error-messages.ts
  export function translateError(error: unknown): string {
    const message = error instanceof Error ? error.message : String(error);
    if (message.includes('duplicate key')) return 'このナンバーは既に登録されています';
    if (message.includes('violates foreign key')) return '関連する顧客情報が見つかりません';
    if (message.includes('LINE API error: 401')) return 'LINE連携の設定を見直してください';
    return 'エラーが発生しました。時間をおいて再度お試しください';
  }
  ```
- `try/catch` ですべての非同期処理をラップし、`translateError` 経由でエラー表示

**完了条件**:
- ユーザーに英語のエラーメッセージが見える箇所がゼロ

#### 4-3. オフライン耐性（ローカル下書き保存）

**対象ファイル**: 新規 `hooks/useFormDraft.ts`

**実装内容**:
- フォーム入力中の値を 1秒 debounce で `localStorage` に自動保存
- ページ再読み込み時に下書きがあれば「下書きから復元しますか？」を表示
- 送信成功時に下書きを削除
- フォーム送信前に意図しないページ遷移時は `beforeunload` で警告

**完了条件**:
- 通信切れ・誤操作で入力データがゼロから書き直しになることがない

#### 4-4. 大きめフォントモード

**対象ファイル**: 新規 `components/FontSizeToggle.tsx`、`app/layout.tsx`

**実装内容**:
- 設定画面（または右上ハンバーガーメニュー内）に「文字サイズ」切替UI
- 小（14px ベース）/ 中（16px、デフォルト）/ 大（18px）の3段階
- ルート要素に `data-font-size="large"` 等を付与し、CSSで全体の `rem` 計算を調整
- ユーザー選択は `localStorage` に保存

**完了条件**:
- 老眼世代でもスマホで快適に読める

#### 4-5. PWA化（ホーム画面追加対応）

**対象ファイル**: `public/manifest.json`、`app/layout.tsx`

**実装内容**:
- `manifest.json` を作成し、アプリアイコン・テーマカラー・スタンドアロンモード設定
- `app/layout.tsx` の `<head>` で manifest を読み込み
- iOS用の `apple-touch-icon` も忘れずに設定
- 必要なアイコンサイズ: 192x192, 512x512, 180x180 (iOS)

**完了条件**:
- Safariで「ホーム画面に追加」するとアプリアイコンとして起動できる
- 起動時にアドレスバーが消えてネイティブアプリのように見える

## Phase 2.5: 業務機能の穴埋め（最優先・準優先）

Phase 1〜2 の操作性改善に続き、**板金屋一人運用で売上・通知に直結する機能**を補う層。Phase 3〜5（UI磨き）とは独立して優先できる。

### 背景

- 見積は自動生成できるが、**明細の手編集**が無いと「概算止まり」になり、顧客送付の実務に耐えない。
- 車検リマインド以外に、**キャンペーン等の任意一斉LINE** を送る導線が無い。
- 公開見積URLはあるが、**スマホからPDF保存**の明示ボタンが無く、顧客・店舗双方で保存しづらい。
- 通知本文に**合計金額・有効期限・車名**を差し込めないと、LINE上で見積の魅力が伝わりにくい。
- 車検 **30日前**・**期限切れ後フォロー** が無いと取りこぼしが出る。

### 2.5-1 見積明細インライン編集

**対象**: `src/app/(app)/quotes/[vehicleId]/page.tsx`、`src/app/api/quotes/[id]/route.ts`（PATCH）、`src/components/quote-line-editor.tsx`（新規）、`src/lib/quote.ts`

**実装内容**:

- `legal_items` / `service_items` を JSON のまま編集。保存時に `computeTotalsFromParts` で税・合計を再計算。
- 行に **値引き（discount）** カテゴリを追加し、負の金額を許容。
- 監査ログ `quote.line_edit`。

**完了条件**:

- 見積カード上で行の追加・削除・保存ができ、公開URL・送信レビューと金額が一致する。

### 2.5-2 キャンペーン送信（minimal）

**対象**: `src/app/(app)/campaigns/new/`、`src/app/api/campaigns/send/route.ts`、`src/lib/providers/line.ts`（multicast）、`supabase/migrations/0010_campaign.sql`

**実装内容**:

- **宛先**: LINE userId 登録済みかつ LINE 配信同意ありの顧客から、チェックで除外可能。顧客IDのカンマ/CSV貼り付けで対象追加。
- **送信**: LINE Messaging API `multicast`（500件チャンク）。本文は全員同一（差し込みは原則使わない旨をUIで注意）。
- **任意**: 画像URL を先頭メッセージとして送信。
- `campaigns` テーブルと `notification_jobs.campaign_id` で履歴を紐付け。

**完了条件**:

- 1回の操作でキャンペーン文面（+任意画像）を複数顧客へ送れ、配信履歴から追跡できる。

### 2.5-3 PDF として保存 + テンプレ変数
