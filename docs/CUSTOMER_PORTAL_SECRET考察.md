# CUSTOMER_PORTAL_SECRET 考察

> 関連: [本番環境構築ガイド.md](./本番環境構築ガイド.md) / [account-roles.md](./account-roles.md)  
> 実装: `src/lib/customer-portal-share.ts` / 差し込み変数 `{{portalUrl}}`

---

## 1. これは何か

`CUSTOMER_PORTAL_SECRET` は、顧客向けポータル URL（`/p/[token]`）を **HMAC 署名するためのサーバー側シークレット**である。

- 顧客のログイン ID／パスワードではない
- 「リンクを知っている人だけが、署名が正しい間だけページを開ける」ための鍵
- トークンには顧客 ID と有効期限が含まれる（既定は約 1 年）

スタッフ画面の「顧客向けポータル」パネルや、LINE／メール本文の `{{portalUrl}}` が、この鍵で作った `/p/...` を指す。

---

## 2. 未設定だとどうなるか

| 箇所 | 挙動 |
| --- | --- |
| 顧客詳細のポータルパネル | 「CUSTOMER_PORTAL_SECRET を設定するとリンクを発行できます」と表示。コピー用 URL なし |
| 通知本文の `{{portalUrl}}` | `/me?cid=<顧客ID>` にフォールバック（レガシー） |
| `/p/...` 自体 | そもそも発行されないので到達しない |

`/me?cid=` は後方互換用で、顧客 ID が URL にそのまま載る。デモや本番で顧客に送る導線としては弱い。

---

## 3. `/p/` と `/q/` の役割

| URL | 秘密鍵 | 用途 |
| --- | --- | --- |
| `/p/...`（`portalUrl`） | `CUSTOMER_PORTAL_SECRET` | お車の状況・見積概要・整備履歴・電話 CTA |
| `/q/...`（`quoteUrl`） | `QUOTE_SHARE_SECRET` | 見積書の詳細・印刷／PDF |

車検系 LINE テンプレ（migration 0016 以降）は、本文に載せる主リンクを **`{{portalUrl}}`（＝`/p/...`）** に寄せている。見積の明細印刷はポータル内ボタンから `/q/` へ進む想定である。

したがって「顧客に送る案内リンク」の是非を考えるときは、まず `CUSTOMER_PORTAL_SECRET` を軸に判断すればよい。見積書を直リンクで送る運用にする場合のみ `QUOTE_SHARE_SECRET` も同程度に重要になる。

---

## 4. 設定すべきか（見解）

### 結論

**顧客に案内リンクを送る環境（本番・クライアントデモ・本番相当の送信テスト）では設定必須。**  
ローカルでポータル画面や送信プレビューを本番相当に近づけたい場合も **推奨**。

値を git にコミットしたり、フロントに埋め込んだりしてはならない。

### 理由

1. **プロダクトの中核導線**  
   本アプリの顧客接点は「リスト → 確認 → 送信 → 顧客がリンクで状況・見積を見る」である。署名付き `/p/` はその出口であり、未設定のまま運用するとレガシー URL に落ちる。
2. **設定コストが低い**  
   長いランダム文字列を環境変数に置くだけ。アプリの機能フラグや追加インフラは不要。
3. **未設定のまま進めるメリットはほぼ無い**  
   開発初期の「とりあえず顧客詳細だけ触る」なら一時的に省略できるが、LINE 送信やポータル確認に入った瞬間に足かせになる。

### 設定しなくてよいケース

- スタッフ UI のみ触り、通知送信もポータル表示も一切試さない短時間の作業
- 意図的にレガシー `/me?cid=` だけを検証しているとき（通常は非推奨）

---

## 5. 運用上の注意

- **他シークレットと共用しない**  
  `OPT_OUT_SECRET` / `QUOTE_SHARE_SECRET` / `CUSTOMER_PORTAL_SECRET` はそれぞれ別の十分に長いランダム文字列にする。
- **ローテーション**  
  鍵を変えると、既に送った `/p/...` リンクは検証に失敗する。変更する場合は顧客への再送や有効期間の説明が必要。
- **漏洩時**  
  漏洩した鍵で任意顧客のポータル URL を偽造できる可能性がある。直ちに鍵を差し替え、Redeploy し、必要なら顧客へ新リンクを送り直す。
- **サイト URL**  
  署名が正しくても `NEXT_PUBLIC_SITE_URL` が `localhost` のままだと、顧客のスマホから開けない。本番では本番ドメインを設定する。

## 6. 置き場所（手順の要約）

詳細手順は [本番環境構築ガイド.md](./本番環境構築ガイド.md) を正とする。

| 環境 | 置き場所 |
| --- | --- |
| ローカル | `.env.local`（または `.env`）に `CUSTOMER_PORTAL_SECRET=...`。dev サーバー再起動 |
| Vercel 等 | Environment Variables に同名で設定し Redeploy |

`.env.example` の `replace-with-another-strong-secret` は必ず差し替える。

## 7. まとめ

| 問い | 答え |
| --- | --- |
| 顧客ログイン用か？ | いいえ。署名付き共有リンク用 |
| LINE に付ける URL か？ | はい。案内フローでは主に `/p/...`（`{{portalUrl}}`） |
| 設定するか？ | 顧客向け案内を使うなら **する**。しない理由はほぼ無い |
| コードに書くか？ | **書かない**。環境変数のみ |
