## 1. テストの進め方

- **順序**: A（自動）→ B（スタッフ）→ C（顧客）→ D（UI/UX）→ E（通知系）→ F（権限）。
- **端末**: PC（Chrome）+ 実機スマホ（iOS Safari / Android Chrome）の両方。可能なら **LINE アプリ内ブラウザ**でも開く。
- **記録**: 各項目に「OK / NG / 保留」と気づきを残す（下記テンプレ）。NG はスクショを添付。
- **判定基準**: 「動く」だけでなく「**初見の店舗スタッフ / 顧客が迷わず使えるか**」で見る。

### 記録テンプレ（コピーして使用）

```text
[項目ID] 結果: OK / NG / 保留
端末: PC Chrome / iPhone Safari / Android / LINE内
気づき:
スクショ:
```

## フェーズ E: 通知・冪等・失敗系

| ID | 手順 | 期待 |
| - | --- | --- |
| E-1 | 個別 LINE 送信 | 到達し `SENT` ログ |
| E-2 | 一括送信 | 件数がトースト表示、各ログ記録 |
| E-3 | 同日・同ルール・同チャネルで再送 | `results[].message` = 冪等ヒット、LINE は再送されない |
| E-4 | `line_user_id` 無し顧客へ送信 | 失敗として記録され、原因が分かる |
| E-5 | 失敗ジョブの再送 | 別チャネル等で再送でき、新ログ追加 |
| E-6 | （メール利用時）MAIL 送信 | DNS 設定済みドメインから到達 |
| E-7 | （メール利用時）存在しない宛先 | `BOUNCED` ログ |

> E-3 の確認後、UI/UX 反復のために一時的に無効化していた場合は `NOTIFICATION_IDEMPOTENCY_DISABLED` を**本番判定前に必ず解除**。

## 10. 不具合トリアージと記録

| 重大度 | 定義 | 対応 |
| --- | --- | --- |
| Blocker | 送信不可・ログイン不可・データ破損・情報漏えい | 本番前に必須修正 |
| Major | 主要導線が使いにくい・誤解を招く表示 | 原則修正 |
| Minor | 軽微な見た目・文言 | 運用開始後でも可 |

- NG 項目は `[項目ID] 重大度 / 症状 / 端末 / スクショ / 再現手順` で起票。
- 修正後は該当フェーズを再テスト（リグレッション）。
